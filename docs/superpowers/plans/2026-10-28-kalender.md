# Gemeinsamer Kalender – Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Die Ansicht „Urlaub" wird zum gemeinsamen Kalender mit eigenen Terminen, Erinnerungen (Login-Hinweis + Glocke) und Meldungsimport für alle mit Schreibrecht; `urlaub.js` entfällt.

**Architecture:** Reine Logik (Normalisierung, Fälligkeit, Gelesen-Schlüssel) in `scripts/br-kern.js`, testbar mit `test-br.js`. Oberfläche, Speicherung und Browser-Zustand in `scripts/br-app.js`, Admin-Menü in `scripts/br-export.js`. `daten.termine` reist auf denselben Wegen wie `daten.urlaub`.

**Tech Stack:** Vanilla JS im Browser (gemeinsamer globaler Scope über fünf `<script>`-Dateien), IndexedDB, `localStorage`, Tests mit Node (`test-br.js`) und Playwright (`test-browser.js`).

**Spec:** `docs/superpowers/specs/2026-10-28-kalender-design.md`

## Global Constraints

- Keine neuen Abhängigkeiten, kein Server, offline lauffähig.
- Jeder Schreibpfad prüft `darfBearbeiten()`; Viewer und Lese-Tab sehen alles, ändern nichts.
- Vorlauf-Stufen exakt: keine Erinnerung (`null`), am selben Tag (`0`), `1`, `3`, `7`, `14` Tage. Standard für neue Termine: `7`.
- Fällig: von `von − vorlauf` bis einschließlich `bis`. „Heute" = lokales Browserdatum (`heuteIso()`). `uhrzeit` beeinflusst die Fälligkeit nicht.
- „Demnächst" in der Glocke: Termine mit `von` in den nächsten 30 Tagen, deren Erinnerung noch nicht fällig ist.
- Gelesen-Schlüssel: `id|von|vorlauf`, gespeichert nur in `localStorage`, nie in `daten`.
- Login-Hinweis nur nach „Datei laden" + Passwort, nicht beim Fortsetzen nach Neuladen.
- `termine` gehört **nicht** in `GREMIUM_FELDER` (Protokollmodul hat keinen Kalender).
- Alle sichtbaren Texte deutsch mit korrekten Umlauten.
- Commits enden mit `Assisted-by: Claude <Modell>`, nie mit `Co-Authored-By`.
- Tests: `node test-br.js` und `node test-browser.js` (Playwright global installiert, `NODE_PATH` gesetzt).

## Review Focus

1. **Termin am Fristtag oder rückwirkend angelegt** → sofort fällig, erscheint in Glocke und beim nächsten Login (Task 1, Test `erinnerungen: am Termintag angelegt`).
2. **`localStorage` wirft oder ist leer** → alles gilt als ungelesen, kein Absturz (Task 6, Test mit überschriebenem `localStorage.getItem`, der wirft).
3. **Viewer/Lese-Tab ruft Import oder Termin-Speichern über eine noch offene Ansicht auf** → keine Änderung an `daten` (Task 4 und 5, Tests mit `sitzungsRolle = 'viewer'`).
4. **Alte Sicherung ohne `termine`** → öffnet ohne Fehler, `daten.termine` ist `[]` (Task 2, Test über `migriere({})`).
5. **Kaputte Termin-Einträge** (fehlender Titel, `bis` vor `von`, Uhrzeit `25:99`, unbekannter Vorlauf) → werden verworfen bzw. auf Standard gesetzt, nicht angezeigt als „Invalid Date" (Task 1).

### Task 1: Termin-Logik im Kern

**Files:**

- Test: `test-br.js`

**Interfaces:**
- Produces:
  - `TERMIN_VORLAUF` – `[{ tage: null, label: 'keine Erinnerung' }, { tage: 0, label: 'am selben Tag' }, { tage: 1, label: '1 Tag vorher' }, { tage: 3, label: '3 Tage vorher' }, { tage: 7, label: '1 Woche vorher' }, { tage: 14, label: '2 Wochen vorher' }]`
  - `isoPlusTage(iso: string, n: number) -> string` (lokales Datum, über `new Date(j, m, t + n)` und `isoTag`)
  - `terminNormieren(liste) -> Termin[]` mit `Termin = { id, titel, von, bis, uhrzeit, notiz, vorlauf, geaendertAm }`. Verwirft Einträge ohne getrimmten `titel`, mit ungültigem `von` oder `bis < von`. `bis` fehlt → `von`. `uhrzeit` nur `/^([01]\d|2[0-3]):[0-5]\d$/`, sonst `''`. `vorlauf` nicht in `TERMIN_VORLAUF` → `7`; `vorlauf: null` bleibt `null`. Fehlende `id` → `uid()`. Sortiert nach `von`, dann `uhrzeit`, dann `titel` (`localeCompare 'de'`).
  - `terminErinnerungAb(t: Termin) -> string|null` (`null` bei `vorlauf === null`)
  - `terminGelesenSchluessel(t: Termin) -> string` = `t.id + '|' + t.von + '|' + t.vorlauf`
  - `erinnerungen(termine, heute: string, gelesen: Set<string>) -> { faellig: Array<{ termin: Termin, gelesen: boolean }>, demnaechst: Termin[] }`
  - `urlaubKalender(...)` liefert je Tag zusätzlich `termine: Termin[]` (Termine mit `von <= iso <= bis`)
